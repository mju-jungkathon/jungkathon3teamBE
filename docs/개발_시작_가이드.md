## 1. 공통 응답 포맷 (`common/`) — 가장 먼저

모든 컨트롤러가 쓰게 되므로 이걸 먼저 만들어야 이후 API가 일관됩니다. 아직 `common/` 패키지 자체가 없습니다.

```java
public record ApiResponse<T>(boolean success, T data, ApiError error) {
    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(true, data, null);
    }
    public static <T> ApiResponse<T> fail(String code, String message) {
        return new ApiResponse<>(false, null, new ApiError(code, message));
    }
}

public record ApiError(String code, String message) {}
```

API 명세서의 공통 에러 코드(`E4001`, `E4010`, `E4030` 등)는 `enum`으로 정의하고, `@ControllerAdvice` 전역 예외 처리기에서 이 코드로 매핑합니다.

같이 만들어야 하는 것:

- `common/config/SecurityConfig` — **지금 이게 없어서 Swagger UI를 포함한 모든 엔드포인트가 Spring Security 기본 Basic 인증에 막혀 있습니다.** 스타터는 이미 올라가 있고 설정 클래스만 없는 상태.
- `common/config/RedisConfig` — refresh token 저장용

## 2. 인증 구현 순서

토큰 발급/검증이 안 되면 이후 거의 모든 API가 `Authorization` 헤더를 요구하므로 전부 막힙니다. 최우선입니다.

1. ~~`User` 엔티티 + `UserRepository`~~ ✔ 완료 (`342a7d5`)
2. `POST /auth/signup` — BCrypt 해시 후 저장
3. `JwtTokenProvider` — access/refresh 토큰 생성·검증 유틸
4. `POST /auth/login` — 인증 성공 시 토큰 2종 발급, refresh token은 Redis에 저장
5. `JwtAuthenticationFilter` — `OncePerRequestFilter` 상속, 모든 요청에서 토큰 검증
6. `POST /auth/refresh`, `POST /auth/logout`

설정 키는 `application-local.yml`에 이미 잡혀 있습니다 (읽는 코드는 아직 없음):

```yaml
jwt:
  secret: ...
  access-token-expiration-ms: 3600000     # 1시간
  refresh-token-expiration-ms: 2592000000 # 30일
```

여기까지 끝나면 Swagger에서 토큰을 발급받아 이후 모든 API를 테스트할 수 있습니다.

## 3. 테스트 전략

현재 테스트는 `AftergrowApplicationTests.contextLoads()` 하나뿐입니다.

| 계층 | 테스트 종류 | 도구 |
|---|---|---|
| Repository | `@DataJpaTest` | Testcontainers(PostgreSQL) |
| Service | 단위 테스트 | JUnit5 + Mockito |
| Controller | `@WebMvcTest` 또는 통합 테스트 | MockMvc |
| 전체 흐름 | E2E | `@SpringBootTest` + Testcontainers |

**H2 대신 Testcontainers를 권장**하는 이유: H2는 PostgreSQL과 문법이 달라서(`gen_random_uuid()`, `TIME` 타입 등) Flyway 마이그레이션 V1~V9가 그대로 돌지 않습니다. 실제 운영과 같은 PostgreSQL 컨테이너로 테스트하는 편이 신뢰할 수 있습니다.

미해결 과제:

- `application-test.yml`이 없어서 CI(`.github/workflows/test.yml`)는 환경변수로만 DB 접속 정보를 주입하고 있습니다.
- Testcontainers 의존성은 아직 `build.gradle`에 없습니다.
- 현재 `./gradlew test`는 로컬 Docker 컨테이너(`docker compose up -d`)가 떠 있어야 통과합니다.
