## 0. 공통 — 이 레포의 테스트 작성 방법 (먼저 읽기)

이 프로젝트는 테스트 방식이 하나로 통일돼 있다: **`@SpringBootTest` + `@AutoConfigureMockMvc` + `@Transactional` 통합 테스트.**
Testcontainers를 쓰지 않고 **실제 Postgres/Redis**(`docker compose up -d`)에 붙는다. 그래서:

- 테스트 실행 전 반드시 `docker compose up -d` (postgres/redis healthy 확인).
- `@Transactional`이라 **DB는 자동 롤백**되지만 **Redis는 롤백되지 않는다** — refresh/rppg 키를 쓰는 테스트는 끝에서 직접 삭제.
- MockMvc import는 Boot 4 패키지: `org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc`.
- 모든 응답이 `ApiResponse`로 감싸져 있으므로 검증은 항상 `$.data.…` (에러는 `$.error.code`).

### 테스트 한 개의 3단계 (기존 `HomeLatestMeasurementTest`가 이 틀)

1. **준비(given)** — 리포지토리로 실제 데이터를 저장하고, 로그인 사용자 토큰을 만든다.
2. **실행(when)** — MockMvc로 실제 HTTP 요청을 보낸다.
3. **검증(then)** — 상태코드 + `jsonPath("$.data.…")`.

### 복붙용 뼈대

```java
@SpringBootTest
@AutoConfigureMockMvc
@Transactional
class ProfileApiTest {

    @Autowired MockMvc mockMvc;
    @Autowired UserRepository userRepository;
    @Autowired JwtTokenProvider jwtTokenProvider;
    // 필요한 도메인 리포지토리 추가 @Autowired

    private String bearer;
    private UUID userId;

    @BeforeEach
    void setUp() {
        User user = userRepository.save(User.builder()
                .email("t-" + UUID.randomUUID() + "@example.com")
                .passwordHash("hashed")
                .nickname("김러너")
                .build());
        userId = user.getUserId();
        bearer = "Bearer " + jwtTokenProvider.createAccessToken(userId);
    }

    @Test
    void 설정이_없는_사용자의_프로필은_기본값을_반환한다() throws Exception {
        mockMvc.perform(get("/users/me/profile").header("Authorization", bearer))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.data.goal.goalType").doesNotExist())
                .andExpect(jsonPath("$.data.integrations.locationLinked").value(false));
    }
}
```

- PATCH/POST 본문은 `.contentType(MediaType.APPLICATION_JSON).content("{\"weeklyRunGoal\":3}")`.
- 검증 실패(E4001) 확인: `.andExpect(status().isBadRequest()).andExpect(jsonPath("$.error.code").value("E4001"))`.
- 실행: `./gradlew test --tests '*Profile*'` (도메인만 골라 빠르게).

### 권장 순서
**profile → home → running** (쉬운 순). 각 이슈 완료 시 `./gradlew test`로 전체 회귀 확인 후 PR.

## 이슈 1 — [test] R7 프로필 도메인 테스트

**브랜치:** `feature/profile-tests`
**라벨:** test

### 배경
프로필은 엔드포인트가 4개(`/users/me/profile|goal|integrations|notifications`)인데 현재 테스트는
엔티티 테스트(`IntegrationStatusTest`) 하나뿐이다. 서비스/컨트롤러에 회귀 안전망이 없다.
정책(설정 없는 유저=기본값 / PATCH=upsert·부분수정 / `weeklyRunGoal @Min(0)`)이 실제로 지켜지는지 고정한다.

### 작업 범위 (테스트 케이스)
- [ ] `GET /profile` — 설정 행이 없는 신규 유저: `goal` 필드 null, `integrations` 전부 false, `notifications` null
- [ ] `PATCH /goal` 최초 호출 → `user_goals` 행 생성(upsert), 응답에 `updatedAt` 채워짐
- [ ] `PATCH /goal` 부분 수정 → `goalType`만 보내면 기존 `weeklyRunGoal` 유지 (그 반대도)
- [ ] `PATCH /goal` `weeklyRunGoal = -1` → 400 `E4001`
- [ ] `GET /integrations` — 행 없으면 네 값 모두 false
- [ ] `PATCH /notifications` → 저장 후 값 반영, `weeklyReportDay`가 `"SUNDAY"`로 왕복
- [ ] (선택) 잘못된 요일 `"MONDAYY"` / 시간 `"25:99"` → 400 `E4001` (HttpMessageNotReadable 경로)

### 완료 조건 (DoD)
- 테스트 3~6개, 로컬 `./gradlew test` 통과(도커 필수)
- 응답은 `$.data.…`, 에러는 `$.error.code`로 검증
- 불필요한 로그/주석 제거

## 이슈 2 — [test] R2 홈 대시보드 테스트

**브랜치:** `feature/home-tests`
**라벨:** test

### 배경
홈은 여러 테이블을 모으는 집계 로직인데 현재 테스트는 "성공 측정 폴백" 한 케이스뿐이다.
주간 집계·오늘 상태·null 방어 같은 핵심 계산이 미검증 상태다.

### 작업 범위 (테스트 케이스)
- [ ] `weeklyRunCount` — 이번 주(월~일) **완료 세션만** 카운트(지난 주 세션·진행 중 세션은 제외)
- [ ] `todayRunningStatus` — 오늘 완료 세션 있으면 `COMPLETED`, 진행 중이면 `IN_PROGRESS`, 없으면 `NOT_STARTED`
- [ ] `remainingToGoal` — `max(0, goal - count)`, 목표(`user_goals`) 없으면 `weeklyGoalCount=0`
- [ ] `weeklySummary` — 총거리 합/평균 bpm/누적 UV 레벨, 데이터 없으면 `0 / null / null`
- [ ] `greeting` — 닉네임 있으면 "안녕하세요, {닉네임}님", 없으면 "러너"
- [ ] (이미 있음) 최근 실패 측정은 건너뛰고 이전 성공 측정으로 폴백 — 유지

### 완료 조건 (DoD)
- 테스트 4~6개, 로컬 `./gradlew test` 통과
- 주 경계(월요일 0시)·오늘 경계 케이스를 `startedAt`을 조절해 검증

## 이슈 3 — [test] R3 러닝 세션 테스트

**브랜치:** `feature/running-tests`
**라벨:** test

### 배경
러닝은 엔드포인트가 5개(prepare·start·live·end + 스트레칭)인데 테스트는 한 시나리오뿐이다.
동시성(이미 진행 중)·소유권(남의 세션) 같은 정책 분기가 미검증이다.
※ `/{id}/heart-rate/select-source`(R4.1)는 heartrate 담당 영역이라 이 이슈에서 제외.
※ R4(heartrate) 머지로 **`/end` 응답에 `defaultHeartRateSource`가 추가**됐다(PR #13). 이 필드는
  `HeartRateMeasurementService.defaultSourceFor()`가 파생하며 running→heartrate 서비스 의존이 생긴 지점이라,
  회귀를 잡기 위해 running 쪽에서도 검증한다.

### 작업 범위 (테스트 케이스)
- [ ] `POST /running-sessions` 시작 → 201, 상태 `IN_PROGRESS`
- [ ] 이미 진행 중 세션이 있는데 또 시작 → 409 `E4090`
- [ ] `GET /{id}/live` — 남의 세션 접근 → 403 `E4030`, 없는 세션 → 404 `E4040`
- [ ] `GET /{id}/live` — `distanceKm`/`intensity` 함께 보내면 스냅샷 갱신 반영
- [ ] `POST /{id}/end` → 상태 `ENDED`, **다시 end 호출해도 에러 없이 현재 상태 반환(멱등)**
- [ ] `POST /{id}/end` — **`defaultHeartRateSource` 파생 검증**: (a) 최근 측정이 있으면 그 source, (b) 측정 이력이 없으면 폴백(애플헬스 연동 시 `WATCH`, 아니면 `RPPG`) — 항상 non-null
- [ ] `GET /prepare` → `locationLabel`/`uvIndex`/`stretching`(Mock 값) 반환
- [ ] `POST /stretching-sessions` → 생성 응답

### 완료 조건 (DoD)
- 테스트 6~8개, 로컬 `./gradlew test` 통과
- 소유권·중복 시작 등 에러 케이스는 `$.error.code`로 검증
- `defaultHeartRateSource`는 heartrate 담당과 겹칠 수 있으니, 러닝 관점(=/end 응답 필드 존재·폴백)만 검증하고 심박수 내부 로직 테스트는 heartrate 소유로 둔다
